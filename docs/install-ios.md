# Tune AV iOS Installation

This guide is for local simulator runs and for installing `Tune AV` on a connected iOS device.

## Use The Guarded Installer

Do not install signed Account AV builds with hand-written `xcodebuild` commands.
Use the guarded installer so the native runtime config is regenerated and
validated every time.

Development device build:

```bash
bun run ios:install:dev
```

Production-flavored device build:

```bash
bun run ios:install:prod
```

Those commands:

- regenerate `apps/ios/Config/Local.xcconfig`
- validate the effective Xcode build settings
- build into an environment-specific DerivedData folder
- install the compiled `.app` on the connected iPhone
- launch the resolved bundle identifier

Use `-- --device <UDID>` when more than one physical iPhone is connected.

## Environment Contract

The installer fails if the resolved Xcode settings do not match the selected
environment.

| Environment | Bundle | Account configuration |
| --- | --- | --- |
| `dev` | `com.avalsys.tuneav.dev` | Generated from local private config |
| `prod` | `com.avalsys.tuneav` | Generated from local private config |

Before building manually, run the same preflight:

```bash
bun run ios:check:dev
bun run ios:check:prod
```

`Local.xcconfig` is generated output. Do not edit it by hand and do not reuse it
after switching environments; regenerate it through the scripts.

## Current signing setup

- Xcode project: `apps/ios/TuneAV.xcodeproj`
- scheme: `TuneAV`
- development team: use your own Apple Developer team when signing for device installs
- device bundle identifier: generated by `scripts/generate-ios-local-xcconfig.sh --env dev|prod`

## Prerequisites

1. Xcode 26.4.1 or later installed
2. An Apple account available in `Xcode > Settings > Accounts`
3. Command line tools selected from that Xcode
4. `bun` 1.3.13 or later
5. Optional private Infisical bootstrap credentials if you need signed Account AV flows

`Local.xcconfig` is gitignored and should be regenerated locally instead of hand-maintained.
Do not copy production values, example secret files, or bootstrap examples into tracked files.

## Switching Dev And Production

Always regenerate the native config after switching between development and
production operator profiles. The guarded installer does this automatically.

## Run on simulator

```bash
xcodebuild -project apps/ios/TuneAV.xcodeproj \
  -scheme TuneAV \
  -configuration Debug \
  -destination 'platform=iOS Simulator,name=iPhone 16,OS=18.5' \
  build
```

You can also open `apps/ios/TuneAV.xcodeproj` in Xcode and run `TuneAV`.

## Manual Install On A Connected iOS Device

Manual installation is only for debugging the installer itself. Run the preflight
first and use the bundle identifier it prints.

Build for the device:

```bash
xcodebuild -project apps/ios/TuneAV.xcodeproj \
  -scheme TuneAV \
  -configuration Debug \
  -destination 'id=<DEVICE_UDID>' \
  -allowProvisioningUpdates \
  DEVELOPMENT_TEAM=<YOUR_TEAM_ID> \
  CODE_SIGN_STYLE=Automatic \
  build
```

Install the generated app:

```bash
xcrun devicectl device install app \
  --device <DEVICE_UDID> \
  ~/Library/Developer/Xcode/DerivedData/TuneAV-*/Build/Products/Debug-iphoneos/TuneAV.app
```

Launch it:

```bash
xcrun devicectl device process launch \
  --device <DEVICE_UDID> \
  <YOUR_DEV_BUNDLE_ID> \
  --activate
```

## First launch trust step

If iOS refuses to open the app after install, trust the developer profile once on the phone:

1. Open `Settings > General > VPN & Device Management`
2. Open the developer app entry that matches the Apple account used for signing
3. Tap `Trust`
4. Open `Tune AV` again from the device home screen

## Known local-dev constraints

- Sign in with Apple is enabled in entitlements. Device provisioning must support that capability for the bundle identifier you use.
- Do not use unsigned compile-only builds to validate Google or Apple sign-in. Clerk native auth stores client and device tokens in Keychain, so auth smoke tests need a signed app with Keychain and Apple Sign In entitlements active.
- If the build hangs in `Resolve Package Graph`, restart Xcode and retry from a clean terminal.
